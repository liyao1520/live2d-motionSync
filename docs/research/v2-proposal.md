# Live2D MotionSync 2.0 实现方案草案

日期：2026-09-16。用户已确认方案并授权在新分支实现。以下保留调研阶段的方案记录；实际实现、依赖版本与验证结果以 [2.0 验证矩阵](./v2-validation.md) 为准。当前分支 codex/v2-modern-player。运行时公开 npm 再分发条件仍待确认。

## 已确认目标

- 不兼容旧 API。
- 支持现代桌面和移动端浏览器，使用框架无关的 TypeScript API。
- 一体化提供模型渲染和口型同步，不要求用户管理 Pixi、internalModel 或帧更新函数。
- 首发覆盖音频文件、MediaStream、流式 PCM。
- 缺少 MotionSync 配置时自动降级为基础音量口型，并公开当前模式；没有可用嘴部参数时明确报告不可驱动。
- 模型验收范围为 Cubism 4/5，逐项公开已验证特性，不支持 Cubism 2，不把所有新版特性视为自动兼容。
- 默认播放打断旧会话；排队必须显式调用。
- npm 安装后即用是硬要求：不能要求调用方另外下载 Core、复制 public 文件或先运行初始化工具。内置分发的授权和构建兼容性仍需核实，不将目标写成已具备能力。
- 已确认优先验证 Untitled，Jannchie 分支作为对照，测试通过后锁定。
- 整体升级工程架构、内置库和工具链，具体见 [工程架构升级方案](./v2-project-architecture.md)。升级包含删去无用依赖、隔离官方代码、严格类型、测试与 CI、发布包验证，不只是提升版本号。
- 首发公开播放控制仅保留播放、停止、显式排队；暂停、恢复、进度跳转、变速等后续增加。PCM 输入的 write/end 和内部背压属于流式输入必需能力，不能随高级播放控制一并删除。
- 模型能力包含基础展示、自适应布局、动作/表情 API、点击命中事件和可关闭的跟随/待机。
- 首发一个框架无关 SDK + JS/React/Vue 完整示例，不发布专用组件包。
- 默认后台节能：停止渲染，文件自动暂挂并在适当时机续播；实时数据不积压。后台自动行为不等于首发公开 pause/resume API。
- 用户新增调研要求：支持压缩包或独立文件直接加载模型。可行性与输入边界见 [模型导入调研](./v2-model-import.md)；首发具体输入范围待确认，未实现。

## 研究结论

推荐 Untitled 作为首选验证对象，Jannchie Pixi 8 分支作为对照；官方 Framework 是接管底层后的后备路线。easy-live2d 的参数覆盖接口虽然简单，但存在需澄清的许可声明冲突以及单模型销毁调用全局 dispose 的风险，当前不宜直接定为默认。

Untitled 的 beforeModelUpdate 在动作、表情、物理之后、Core update 之前，适合最终写入口型参数。它自带的 motionSync 配置不等于官方 Cubism MotionSync。仅使用现代入口，显式配置 WebGL，关闭内置音频口型，统一由我们的音频模块管理输入与播放。物理先于此 hook，若要求嘴部同帧影响物理，需要另行验证和设计。

官方 Web MotionSync 最新公开 tag 为 5-r.2；本项目当前分析框架已与官方较接近。升级重点是围绕官方分析器重建产品层，而非盲目复制官方 Sample。Framework tag 与专有 Core 的版本分别记录、校验与锁定。

证据详见 [渲染器调研](./v2-renderer-research.md)、[MotionSync 调研](./v2-motionsync-research.md)、[现有代码审阅](./v2-current-code-audit.md)。所有候选仍未经本项目运行时验收，不能承诺性能优劣。

## 建议架构

公开入口只提供 Player：初始化、模型显示、音频播放/接入、状态订阅与销毁。内部按下表拆分职责，初期不必为每个模块发布单独 npm 包；新增模型导入层仍隐藏在同一公开入口后。

| 内部模块 | 职责与边界 |
| --- | --- |
| RuntimeLoader | 自动加载随产品交付的运行时，版本/能力校验、并发去重、明确失败；内置分发具体形式须通过授权与构建验收 |
| ModelAssetBundle / Resolver（新增建议） | URL/ZIP/文件集合统一资源解析，模型入口发现、依赖检查、Blob URL所有权；渲染和MotionSync共用 |
| RendererAdapter | 模型加载、布局、动作/表情、命中交互、参数写入时机及清理；不把上游内部类型泄漏到常用 API |
| AudioSession | 三类输入、时钟、解码/声道/重采样、播放控制、有界缓冲、取消和结束 |
| LipSyncDriver | 官方 MotionSync 与基础振幅模式；映射、平滑、增益与静音处理；输出参数结果 |
| Player | 组合各模块，维护生命周期和事件；释放自身资源，保护外部传入资源 |

## API 草图（用于讨论，非已实现接口）

```ts
const player = await createLive2DPlayer({
  canvas,
  model: '/models/character.model3.json',
  layout: { fit: 'contain' },
  lipSync: { mode: 'auto' },
});

// 在用户点击等手势回调中解锁；不尝试绕过浏览器自动播放限制。
await player.unlockAudio();

const speech = player.play('/audio/hello.wav');
await speech.finished;

// 显式排队；新 play 默认替换当前会话并清空旧队列的具体语义待 API 轮次确认。
const queued = player.enqueue('/audio/next.wav');

const microphone = player.attachStream(mediaStream, { monitor: false });
microphone.stop();

const stream = player.createPcmStream({
  sampleRate: 24000,
  channels: 1,
  format: 'f32',
});
await stream.write(chunk); // 有背压；不能无限排队。
await stream.end();        // 输入结束、排空播放后完成。

await player.destroy();
```

普通接入不要求配置 Core 路径；自动资源加载是交付验收项。play 默认打断，enqueue 显式排队。建议立即返回会话句柄，加载错误通过 finished 及结构化事件报告；正常结束与主动停止使用明确结果，实际失败使用错误。公开暂停/恢复、seek、变速已经排除首发；不为不同输入提供虚假的统一控制能力。

### 最后待确认的会话语义建议

- `player.play()` 替换当前输入并清空此前等待队列；`player.stop()` 停止当前输入并清空队列。一次用户打断不能在稍后重新播放旧回答。
- `player.enqueue()` 首发只接受有限音频（URL/AudioBuffer），FIFO 播放；某项失败单独报告并继续下一项，停止/替换导致的队列项以 cancelled 结果结束。
- `attachStream()` 和 `createPcmStream()` 创建当前输入会话，替换旧输入；PCM 的 write 不另建会话，end 标记输入结束并等待已接受的数据播放完成。流式会话不放入文件等待队列。
- `finished` 返回 completed/cancelled 等可区分结果；加载/解码/分析失败进入 error。错误必须同时可通过类型化事件观察，库内部处理未被调用方订阅的完成 Promise，避免无人 await 时产生无意义的全局未处理拒绝。
- 单个模型同一时刻只有一个口型输入，多模型独立；模型动作里的音轨不通过上游偷偷播放，交给统一音频所有权策略或显式禁用。
- 外部传入的 MediaStream 音轨不由 stop/destroy 关闭；首发不强求公开注入外部 AudioContext，内部管理共享上下文与引用计数。
- 首发 PCM 为有序原始样本输入，支持显式格式与采样率；不包含任意 MP3/AAC 压缩网络分片解码、WebSocket 重连或 TTS 服务商 SDK。

### 后台行为细化建议

文件保留播放位置并自动暂挂，回到前台仅在浏览器允许恢复时续播，否则报告需要用户激活。MediaStream 不缓存后台历史样本，恢复使用当前数据。PCM 按实时模式处理：后台使输出静音并不积累待播历史；仍接受输入时丢弃已过期数据并更新媒体位置，前台不补播旧语音。如果浏览器冻结了 JS/Worklet，恢复时重置 generation/缓冲并从新的有效输入接续；不能保证冻结期间 JS write 或网络回调继续执行。需要保留完整 PCM 历史的行为属于后续可配置策略，不应默认建立无限缓存。

丢弃后台数据会使 TTS 语音不完整，需要在文档明确；这是选择“实时不积压”的产品结果。按时间戳丢弃尚需定义输入时间基，首发不擅自假定服务器与浏览器时钟同步。

## npm 安装即用的交付约束

用户已否决“一次性手动准备官方 Core”的默认路线。研究优先级调整为：确认可随产品交付的官方原始文件及条件 → 验证包内资源自动加载 → 再锁定打包实现。

- 将库代码、Cubism Core、MotionSync Core、AudioWorklet 及需要的辅助资源作为完整交付链检查。只有 npm tarball 含文件并不等于浏览器能够寻址。
- 若确认允许分发，优先研究保留官方文件原始字节的独立资源方式，避免当前 raw + inline script 的实现作为唯一方案。运行时按需初始化；纯渲染或基础口型模式不应强制初始化 MotionSync 分析器。
- `new URL('./asset', import.meta.url)` 是候选资产寻址机制，不能凭通用文档就保证发布到 node_modules 后所有打包器均正确处理；Vite 官方也明确提示 SSR 语义差异。需从 npm pack 产物安装到干净消费项目，验证 Vite 开发/生产、Webpack 5，以及项目已有 Next.js 路线的客户端加载和 SSR 导入。
- 验收要求不依赖消费者手工复制文件、特殊 loader 或安装时下载脚本；若某条构建链无法实现，则公开缩小支持矩阵或在产品层重新讨论，不能悄悄增加步骤。
- 默认不把未经授权核实的第三方 CDN 当作解决办法。公共 CDN 分发同样有分发条件，且引入外网和可用性依赖；是否允许默认外网依赖尚未由用户决定。
- 严格 CSP、Blob URL、WASM 编译权限和静态资源路径均需实际测试；可提供高级资源路径覆盖，但不能成为普通接入前提。
- 自动加载运行时不包括提供用户模型，也不能绕过浏览器播放手势和麦克风权限。

技术依据：[Vite 静态资源文档](https://vite.dev/guide/assets)、[Webpack Asset Modules](https://webpack.js.org/guides/asset-modules/)。[运行时分发专项核查](./v2-runtime-distribution.md)已完成公开材料检索：有附条件再分发条款及不带 Core 的库分发案例，但不足以确认本项目随 npm 附带两个 Core 的具体形式。此项作为发布依赖保留，不改回用户手动准备资源的方案。

## 音频与同步设计

文件解码后、采集流以及外部 PCM 都进入明确采样率和声道格式的处理路径。分析配置中的 analysisFps 与 PCM sampleRate 分离。输入采样率变化不得继续复用旧 processor 状态。

播放由音频时间线调度；分块不能等待前块 ended 才启动。Worklet 处理实时采集/播放，消息按块批量传递；主线程先承担官方分析，是否迁入 Worker 由基准决定。不把 SharedArrayBuffer 和跨域隔离作为默认部署要求。

PCM 缓冲有容量和背压；实时流的过载策略与文件/可回压 PCM 分开定义。记录已消费音频位置，渲染读取与播放位置对应的分析结果，而不是简单使用最新收到的网络分块。同步偏移可调，区分采集延迟、缓冲延迟和输出设备延迟。

会话 generation 隔离停止后的回调，取消同时覆盖网络、解码结果采用、音频调度与口型状态。底层解码不可中断时丢弃过期结果，不能把 AbortSignal 描述成保证所有浏览器操作立即终止。

## 健壮性与配置

- 生命周期至少区分加载、就绪、销毁中、已销毁；播放状态独立维护，避免暂停音频被误认为卸载模型。
- 导入无 DOM/AudioContext 副作用；初始化失败可清理，destroy 幂等。
- MotionSync 配置缺失、配置损坏、网络失败分别诊断，禁止把所有错误静默伪装成基础模式。
- 配置按运行时、布局/渲染、音频、口型分组；常规接入保留默认值。
- 音频配置候选包括输出音量、缓冲上限、声道选择/下混、采样率与同步偏移；口型配置包括模式、参数映射、权重、增益、门限、平滑、静音释放时间。
- 暴露加载/能力/模式变化/播放结果/欠载等类型化事件；诊断默认不逐帧刷日志。
- 自己创建的资源自己释放；用户传入的 MediaStream 音轨默认不停止，外部 AudioContext 默认不关闭。最终所有权策略仍需在 API 轮次确认。

## 实施阶段与验收

1. **选型验证**：锁定实际 npm 产物与 Framework/Core 组合；同模型对照 Untitled/Jannchie，验证最终写入 hook、动作/表情并行、多实例销毁、移动端与 WebGL 恢复。
2. **最短文件链路**：运行时加载器、Player、模型布局、文件播放、官方口型和基础降级；产出最小接入示例。
3. **实时链路**：MediaStream 与流式 PCM、统一时间线、有界缓冲、背压、断流恢复、连续打断。
4. **生命周期和质量**：失败恢复、异步竞争、资源所有权、SSR 导入、多实例与长时间运行。
5. **发布与文档**：校验发布包入口/类型/资源路径；原生 JS、React、Vue 示例；迁移说明直接介绍新 API，不提供旧 API 兼容层。

验证包括：404/解码失败、切源与连续打断、刚好消费完 PCM、16/24/44.1/48 kHz、立体声、静音与尾音、缺配置/缺嘴部参数、标签页切换、iOS 音频解锁、加载中销毁、双实例销毁其中一个。性能在固定设备/模型/DPR 下记录帧耗时 p50/p95、分析耗时、声画偏移、长任务和长期内存趋势，再给出发布阈值。当前无实测数据，不写虚假的“性能提升百分比”。
